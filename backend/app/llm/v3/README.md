# LLM V3

V2의 도구 호출 에이전트·벡터 검색·제품명 표기 정규화를 기반으로 만든 독립 버전입니다.
V1/V2 코드를 런타임에 import하지 않습니다. 기존 버전 파일은 변경하지 않습니다.

## 변경점

- 일반 주의사항: 복용 금지 대상 → 중대한 이상반응 → 복용 중 주의 순서로 3~4개 항목을 안내합니다. 질문하지 않은 성분 설명이나 별도 병용 목록을 덧붙이지 않도록 지시합니다.
- 임신 등 상황 질문: 해당 상황의 근거만 설명하며 금기·상담 권고·자료 부재를 구분합니다. 이 부분은 생성 프롬프트 정책이므로 실제 모델 회귀 평가가 필요합니다.
- 제품 식별: V2의 밀리그램/밀리그람/mg 표기 정규화와 제조사 확인을 유지합니다. 병용 질문에서 확인된 제품, 후보가 여러 개인 제품, 찾지 못한 이름을 구분해 한 번에 요청합니다.
- RDS 의약품 조합: V1 `interactions.py`의 Python 판정을 가져왔습니다. 모든 제품쌍을 비교하며 품목 DUR, 성분 기준 주의, 동일 성분 중복, 비교 코드 누락을 구분합니다.
- Gold 조회는 `gold_safety.py`: 성분명 exact unique일 때만 누락 코드를 보완합니다. 여러 코드가 있으면 선택하지 않습니다. 성분 규칙은 양방향을 조회하며 제품 간 조합에만 적용합니다.
- 효능군 중복은 투여경로가 둘 다 경구로 확인된 경우만 적용합니다. 용량 참고값을 개인 복용량으로 안내하지 않습니다.
- 의약품+건강기능식품은 성분 금기 비교 없이 `gold.health_food.iftkn_atnt_matr_cn`을 읽습니다. 의약품 2개+건강기능식품이면 의약품끼리의 판정도 함께 제공합니다.
- LLM에는 Python 판정과 원문 조건을 전달해 읽기 쉬운 설명을 요청합니다. LLM이 금기를 직접 판정하지 않지만 최종 생성문은 배포 후 평가가 필요합니다.

### 서비스 페이지 점검 후 수정 (2026-10-23)

- 위기 표현 보강: "수면제를 모아두고", "사라지고 싶어요", "깨어나지 않았으면" 등을 위기로 처리합니다(`safety.CRISIS_PATTERN`).
- 병용 질문의 제품 수: 6개 이상이면 "5개까지" 안내, 같은 약을 두 번 넣었거나 하나뿐이면 다른 약을 알려 달라고 코드 문구로 안내합니다(모델이 도구를 안 불렀을 때도).
- 띄어 쓴 이름("타이레놀 500mg")을 전체로 못 찾으면 첫 단어로 다시 찾고, 함량 숫자가 이름에 든 제품으로 좁혀 되묻습니다(`search._find_by_brand`, 근사 일치).
- 근거 문단은 있었지만 답변 첫 문장이 "확인할 수 없어요/찾지 못했어요"이면 `status`를 `no_evidence`로 바꿉니다(답변 문장은 유지).
- 프롬프트: 제품명 표기 유지, 자료에 없는 연결 금지, 나이로 해당 여부 짐작 금지, 평가 표현 금지, 구간별 용량은 원문대로, 증상 질문은 [범위밖]이 아님.
- 2차 점검 후: 질문 속 제품 + 사진 제품이 6개 이상이면 모델이 `[제품수초과]`를 내고 코드가 5개 안내로 바꿉니다. 병용 질문인데 약이 하나뿐이면 그 약의 상호작용 항목을 보여 주고 다른 약 이름을 요청합니다. 제품은 찾았지만 관련 문단이 없으면 "약 이름을 다시 입력" 대신 "'○○'의 등록된 정보에서는 물어보신 내용을 찾지 못했어요"로 안내합니다. 도구에 넣는 제품명은 사용자가 쓴 표현을 줄이지 않습니다.

## URL / 설정

백엔드 재시작 후:

- `/api/llm/v3/docs`
- `/api/llm/v3/ask` (POST)
- `/api/llm/v3/models`, `/api/llm/v3/health`

`backend/app/main.py`에서 V3 앱을 mount하고 수명주기를 연결합니다. 기존 `/api/` Nginx 프록시를 그대로 사용합니다.
V3는 X-API-Key 인증 없이 호출합니다(헤더를 보내도 무시합니다). `LLM_V3_API_KEY`·`LLM_V2_API_KEY` 설정과 관계없이 열려 있으므로, 남용 방지는 동시 처리 제한(`LLM_V3_API_MAX_CONCURRENCY`, 기본 4)에 의존합니다. 공개 서비스라면 Nginx 등 앞단에서 요청 수 제한을 거는 것을 권장합니다.
V3 설정은 `LLM_V3_*`가 우선, 같은 이름의 `LLM_V2_*`는 호환 기본값입니다.
DB 호스트는 기존 `pill-check/dev/app` 시크릿의 `DB_HOST`를 사용합니다. EC2 인스턴스 역할 인증을 유지합니다.
V1 Python 판정은 RDS 모드에 적용됩니다. `LLM_V3_CONTRA_SOURCE=rds`로 명시할 수 있으며 기본 auto도 로컬 SQLite 파일이 없으면 RDS입니다.

```json
{
  "question": "셉트린정 주의사항 알려줘",
  "products": []
}
```

```json
{
  "question": "이 약들 같이 먹어도 되나요?",
  "products": ["셉트린정", "타이레놀정500밀리그램", "고려인삼분말캡슐"]
}
```

V2 API 계약을 유지하므로 요청에 `model` 필드는 없습니다. 모델은 `LLM_V3_DEFAULT_MODEL=haiku` 또는 `sonnet`으로 설정합니다.
usage도 V2의 LLM 호출 집계(캐시 읽기/쓰기 별도)를 유지하며 임베딩 사용량은 포함하지 않습니다.

## 검증

```powershell
$env:PYTHONDONTWRITEBYTECODE='1'
$env:PYTHONPATH='backend'
python -m app.llm.v3.tests.run
```

가짜 DB·모델로 실행하며 실제 AWS/DB 호출은 없습니다. V2 호환 동작, V1 판정, V3 도구 통합과 mount된 Swagger(인증 없음)를 검증합니다.
실제 DB 데이터와 Bedrock 모델의 답변 품질 및 비용은 배포 후 별도 검증해야 합니다.

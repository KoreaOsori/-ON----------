# 배포 후 Haiku / Sonnet 비교

2026-10-22 로컬 Python HTTP 클라이언트에서 지정된 `/api/llm/v1/ask`로 같은 5개 시나리오를 모델별 1회씩 전송했다. EC2 접속/명령 실행은 하지 않았다. 클라이언트 재시도는 없었다. 최초 샌드박스 실행은 DNS 실패로 서버에 도달하지 못했으며 아래 집계에서 제외했다.

원본: `comparison_20261022_151706.json`. DNS 실패 기록: `comparison_20261022_151651.json`.

| 시나리오 | Haiku | 시간 | Sonnet |
|---|---|---:|---|
| 코푸시럽·셉트린정·코데농정12345 | 확인 필요 이름 특정, 확정 제품 재요청 없음 | 3.505초 | 503 |
| 용각산·원비디 병용 | 금기 미발견과 안전 보장 구분. 매핑 설명에 모순이 남음 | 3.916초 | 503 |
| 코푸시럽 주의사항·부작용 | answered로 완결된 답변, 이전 미완료 안내 재현 안 됨 | 10.601초 | 503 |
| 코푸시럽·오메가3 | 오메가3만 제품명 확인 요청 | 3.370초 | 503 |
| 코데농정12345 제외, 용각산 효능만 | 제외 제품 재언급 없이 효능만 답변 | 2.361초 | 503 |

Haiku HTTP 200: 5/5, 평균 4.751초, 범위 2.361~10.601초. Sonnet HTTP 503: 5/5, 평균 0.680초(실패 응답 시간이며 추론 속도 비교 대상 아님).

모든 응답/오류 본문은 status, answer, usage의 3개 필드다. Haiku usage에는 routing만 있고 Sonnet 오류 usage는 빈 객체다. 모델 별칭 요청은 확인했지만 응답에 실제 Bedrock 모델 ID가 없으므로 서버의 실제 모델 매핑은 이 테스트로 검증할 수 없다.

## 확인된 개선과 남은 문제

- 단일 약 주의사항 답변의 미완료 문제와 제외 제품 재언급은 이번 표본에서 재현되지 않았다. 응답에는 stopReason이나 재작성 횟수가 없으므로 재시도가 실행되어 해결됐는지는 알 수 없다.
- 불명확한 제품만 다시 묻고 확정된 제품의 정보를 재요청하지 않았다. 다만 확인 요청이 여전히 1~3문장 목표보다 길다.
- 용각산·원비디 응답은 처음에 두 제품 모두 일부 성분 코드가 연결됐다고 설명한 뒤 용각산에는 코드가 없다고 설명하여 내부적으로 모순된다. 성분별 확인 수치도 제공하지 않고 DUR 코드라는 전문용어를 노출한다. 구조화된 mapping_coverage를 더 정확히 설명하도록 개선이 필요하다.
- 같은 답변에서 포장의 전체 성분을 약사에게 확인하도록 권한다. 사용자가 전체 성분표를 다시 입력하도록 요구하지는 않지만 미확인 범위에 집중하는 목표에는 미흡하다.
- Sonnet은 모든 요청이 약 0.6~0.7초에 동일한 일반 오류로 종료된다. 모델 경로의 설정/권한/가용성 문제 가능성이 있지만 공개 응답만으로 원인을 확정할 수 없다. 서버의 `LLM v1 Bedrock failure: <code>` 또는 `LLM v1 dependency unavailable` 로그와 Sonnet 모델 매핑을 확인해야 한다. 서버 로그에는 이번 작업에서 접근하지 않았다.

## 판정 범위

Haiku의 기본 응답 흐름은 개선됐으나 설명 일관성과 간결성은 추가 보완이 필요하다. Sonnet은 가용성 실패로 품질 비교 불가다. 각 질문을 모델당 한 번만 실행한 소규모 점검이며 안정성/비용 우열을 판정할 수 없다. routing 토큰만 노출되므로 전체 추론 비용도 비교할 수 없다.

Gold 원문 및 벡터 조회 로그를 직접 대조하지 않았으므로 임상적 정확성, 실제 벡터 사용 여부, 금기 조건 누락 여부를 검증한 것은 아니다. 실재 건강기능식품을 확정한 조합과 공식 DUR 금기 양성 사례도 이번 5개 시나리오에는 포함되지 않았다.

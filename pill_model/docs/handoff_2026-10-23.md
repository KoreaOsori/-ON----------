# 사진 인식(알약·처방전) 연동 — 2026-10-23 master 반영 내용

작성: 서동현 (OCR·CNN 담당) / 브랜치 `OCR/CNN` → `master`

## 한눈에 보기
```
[프런트] 사진 첨부 → 사진 종류 선택(알약 / 처방전·약봉투)
   │ POST /api/v1/uploads/presign  →  S3 업로드 버킷에 직접 PUT (pill/… · prescription/…)
   ▼
[백엔드] POST /api/v1/pill/*            → 워커 /pill/*   (각인 OCR + CNN 외형 → 후보·대화 단계)
         POST /api/v1/ocr/prescriptions → 워커 /rx/*     (OCR → 개인정보 차단 → Haiku 구조화 → 허가목록 매칭)
   │ object key 만 전달, 헤더 X-Worker-Token
   ▼
[pill_model 워커] 별도 EC2 · Docker · 백엔드 SG 에서 오는 8000 만 허용
```

## 개인정보
- 처방전·약봉투 사진, 읽은 글자, LLM 입출력은 워커에서 저장·로그하지 않음 (로그는 장 수·시간·약 개수·판정 종류만)
- 알약은 사용자가 동의했을 때만 배경 제거된 알약 조각을 모델 버킷 `crops/` 에 저장 (경로에 사용자 ID 없음)

## 운영 반영에 필요한 것 (아직 안 함)
1. 워커 EC2: `git pull` → `bash scripts/fetch_models.sh` → `.env` 작성 → `docker compose up -d --build`
2. 백엔드 EC2 `.env` 3줄 추가 후 재시작
   ```
   OCR_PROVIDER=worker
   PILL_WORKER_URL=http://<워커 프라이빗 IP>:8000
   PILL_WORKER_TOKEN=<워커 .env 의 WORKER_TOKEN 과 같은 값>
   ```
   값을 넣기 전에는 기존처럼 동작함 (사진 인식 요청만 "아직 연결되지 않았어요" 503).
3. 프런트 재배포
